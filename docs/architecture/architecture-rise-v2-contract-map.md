The runtime was ANGLE SwiftShader and GPU timer queries were unavailable. All timings are CPU-submit or frame-cadence observations, not GPU execution time or hardware FPS; do not set an FPS threshold from them.

The targeted Architecture Rise snapshot above uses the repository’s existing scene-capacity-snapshot instrumentation and is the baseline for planning; PR B must capture its latest main parent as a matched before-state and record any full-matrix harness failure honestly.

## Known test and capture limitations to carry forward

- The existing Architecture Rise focus-range E2E has an observed intermittent failure at its 5-second canvas-mount assertion on cold/combined runs; the same test passed when isolated in PR #338 review-fix evidence.
- The standard Dream Loop capture has previously been blocked by fixed-port contention and has timed out in its existing overlay-toggle loop after the teaching frame. Do not weaken or bypass it in PR A.
- PR B must establish clean Observer and teaching captures, plus a focused public-control readiness check. PR C must demonstrate the actual clean-capture harness works before any visual loop starts. Keep these issues explicit if still reproducible.
