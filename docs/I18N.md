# Internationalization foundation

The application uses bundled `i18next` resources with `react-i18next` for
learner-facing site, public-catalog, and migrated simulator teaching copy.

## Current contract

- Supported locales are `en` and `zh-HK`; English is the default and fallback.
- Initial resolution is a valid persisted preference, then the browser
  language (`zh`, `zh-*`, and `zh-TW` map to `zh-HK`), then English.
- The preference is stored as the locale identifier under
  `view-camera-simulator.locale` when storage is available.
- Message keys describe semantic UI concepts such as
  `home.focusCta.title` and `scenes.mirrorShift.description`; English
  sentences are not keys.
- English resources define the canonical message shape. Each locale module is
  checked against that shape with TypeScript.
- Translated strings are presentation data only. Scene IDs, routes, task IDs,
  evaluator logic, and simulator state continue to use stable identifiers.

Resources are split by surface under `src/i18n/messages/<locale>/`. Add a new
message to the English module first, then add the equivalent message to every
supported locale module. Keep the pedagogical and terminology contract in
[`LEARNING_MODEL.md`](./LEARNING_MODEL.md) authoritative when translating.

The locale state is global and persists while navigating into the full-bleed
simulator, but the simulator header does not currently expose a language
selector. Free Practice teaching copy and Movement Help now use the simulator
message catalog. Guided Task, evaluator, readout, and diagnostic copy remain
deferred; translation remains presentation-only.
